## 2. 정규화·WLC 명세 (데이터 없이 지금 확정 가능)

- **WLC 식**: `S = Σ_j w_j · x_j`. 근거: [M08] Malczewski WLC(2000), [M09] Local WLC, [M14] ArcGIS Weighted Overlay(percent influence·suitability scale), [M15] UK MCDA.
- **정규화**: 축 내 지표 = 상권-업종-분기 모집단 대비 백분위(0~100) 유지(현행 계승). [M08]이 경고한 척도·측정단위 문제를 백분위로 회피. 필요 시 min-max 병기.
- **방향**: 편익형/비용형을 지표 단위 명시. 비용형(임대료·실거래가)은 `100 - 백분위`. 근거: [M14][M18].
- **위험태도(선택)**: 보수형/공격형 점수는 OWA로 표현 가능. 근거: [M10] Ordered Weighted Averaging.
- **제약(마스크)**: 표본 과소·결측 상권은 제외 또는 신뢰도 감점. 근거: [Q13](공간데이터 품질), [Q08](DQV).

## 9. 전처리 전 확인사항: 위치·업종 입력 구조

현재 리포트/알고리즘 테스트처럼 사용자가 상권명과 업종명을 정확히 입력하는 방식은 임시 검증용으로만 본다. 실제 구조에서는 사용자가 이름·코드·상권명을 외우지 않아도 되도록, 화면 입력을 내부 표준 키로 변환해야 한다.

### 9.1 업종 선택 구조

- 최종 알고리즘 입력 키는 `서비스_업종_코드`를 기준으로 한다.
- 화면에서는 `대업종 -> 중업종 -> 세부업종` 드릴다운으로 선택하게 한다.
- 세부업종 선택 결과만 알고리즘에 전달한다.
- 예: `음식점업 -> 한식 음식점업 -> 한식음식점 -> CS100001`.
- 사용자가 업종명을 직접 외우는 방식은 쓰지 않는다. 검색 자동완성은 보조 수단으로만 둔다.

확인된 근거 파일:

- `datacorpus/_final/spatial_od/SBDC_업종분류표_247.csv`
  - `대분류코드`, `대분류명`, `중분류코드`, `중분류명`, `소분류코드`, `소분류명` 보유.
- `datacorpus/_final/spatial_od/업종코드_서울_SBDC_매핑검증.csv`
  - 서울시 `서비스_업종_코드/명`과 SBDC 대·중·소 업종 후보 매핑 보유.

주의:

- 서울 상권 API의 핵심 단위는 `서비스_업종_코드/명`이다.
- SBDC 대·중·소 분류는 사용자 선택 UX와 업종 그룹화에 사용한다.
- 자동 매칭이 약한 업종은 전처리 전에 수동 확정 매핑표로 보정해야 한다.

### 9.2 위치 선택 구조

- 최종 알고리즘 입력 키는 `상권_코드`를 기준으로 한다.
- 화면에서는 사용자가 상권명을 정확히 외워 입력하지 않게 한다.
- 가능한 입력 방식은 다음 순서로 둔다.

1. 지도 클릭
   - 클릭 좌표를 얻는다.
   - 해당 좌표가 포함된 상권 polygon을 찾는다.
   - 포함 상권이 없으면 가장 가까운 상권 또는 인접 상권 후보를 보여준다.
2. 주소/장소 검색
   - 카카오 등 지오코딩으로 좌표를 얻는다.
   - 좌표를 상권 polygon 또는 인접 상권으로 변환한다.
3. 행정구역 선택
   - `자치구 -> 행정동 -> 상권 후보` 순서로 좁힌다.
4. 상권명 자동완성
   - 예: `강남`, `홍대`, `이태원` 검색 시 관련 상권 후보를 보여준다.

주의:

- 상권명 목록을 코드에 하드코딩하지 않는다.
- 위치 목록은 전처리된 `상권 마스터 테이블`에서 읽는다.
- 지도 클릭 분석을 위해서는 상권 polygon 기준의 point-in-polygon 매칭이 필요하다.
- polygon 밖 좌표는 최근접 상권, 인접 상권, 행정동 기준 후보를 함께 반환한다.

| `trade_area_boundary` | 상권 polygon·중심점·좌표계 | `상권_코드` |
| `industry_master` | 서울 서비스업종 코드·명 | `서비스_업종_코드` |
| `industry_hierarchy` | 대·중·세부 업종 선택 구조 | `대분류코드`, `중분류코드`, `서비스_업종_코드` |
| `industry_mapping_review` | 서울 업종과 SBDC 분류의 확정 매핑 | `서비스_업종_코드` |

알고리즘 호출 계약:

```text
사용자 입력: 지도 클릭 / 주소 / 장소명 / 행정구역 / 업종 선택
전처리·매칭: 좌표 또는 이름 -> 상권_코드, 업종 계층 -> 서비스_업종_코드
알고리즘 입력: 상권_코드 + 서비스_업종_코드
리포트 출력: 사람이 읽는 상권명 + 업종명 + 점수 근거
```

따라서 전처리 단계에서는 모든 데이터를 하나의 거대 파일로 합치지 않는다. 상권, 업종, 좌표, 매출, 점포, 인구, 교통, 임대비용 등은 원천 단위와 시간 단위를 보존한 표준 테이블로 나누고, 리포트 생성 시점에 필요한 키로 조인한다.
