# 알고리즘 근거 자료 검증 감사

작성일: 2026-06-30

## 1. 감사 대상

대상 폴더:

`research/algorithm_evidence_sources/`

감사 기준:

- 원문 파일이 실제로 저장되었는가
- PDF 파일이 HTML 오류 페이지가 아닌 정상 PDF인가
- 공식 출처와 로컬 파일이 카탈로그에 연결되어 있는가
- HTML 파일은 공식 문서이며 정제요약이 있는가
- 수집 과정과 실패 항목이 기록되어 있는가
- 알고리즘 강화에 필요한 방법론/수식/원천데이터/품질기준이 모두 포함되는가

## 3. PDF 서명 검증

검증 명령:

```powershell
$bad=@()
Get-ChildItem research\algorithm_evidence_sources -Recurse -File -Filter *.pdf | ForEach-Object {
  $bytes=[System.IO.File]::ReadAllBytes($_.FullName)
  $sig=[System.Text.Encoding]::ASCII.GetString($bytes,0,[Math]::Min(5,$bytes.Length))
  if($sig -ne '%PDF-'){ $bad += $_.FullName }
}
if($bad.Count){ $bad } else { 'ALL_PDF_SIGNATURES_VALID' }
```

결과:

`ALL_PDF_SIGNATURES_VALID`

## 6. HTML 자료 검증

HTML 파일은 다음 조건을 만족하는 경우만 보관했다.

- 정부/공공기관/표준기관/공식 제품 문서
- PDF 원문이 없거나 HTML이 최신 공식 문서
- 알고리즘 입력 또는 데이터 신뢰도 항목으로 정제 가능

정제 요약:

`cleaned_notes/공식_HTML_정제요약_20260630.md`

## 7. 실패 항목 검증

다운로드 과정에서 PDF 확장자로 HTML 오류 페이지가 저장된 사례가 있었다.

조치:

- 1KB 미만 파일 검사
- `%PDF-` 서명이 없는 파일 삭제
- 실패 항목은 `수집_진행로그_20260630.md`에 보류로 기록

대표 실패:

- MDPI Fuzzy TOPSIS PDF 직접 다운로드 실패
- USDA NRCS 원 PDF 직접 다운로드 실패
- KREAA PDF 직접 다운로드 실패
- SNU 논문 PDF 직접 다운로드 실패
- 서울신보 일부 첨부는 서버 제한으로 재시도 후 정상 파일만 보관

추가 보강:

- 서울신보 지역밀착 상권현황 리포트 26-2호는 초기에는 대표 3개 구만 확보했으나, 이후 다운로드 간격을 늘려 25개 자치구 PDF 전체를 `reports/seoulshinbo_local_commerce_26_2/`에 추가 수집했다.

## 8. 알고리즘 요구사항별 커버리지

| 요구 영역 | 커버리지 | 근거 |
|---|---|---|
| 점수화 방법론 | 충족 | WLC, MCDA, AHP, TOPSIS, Weighted Overlay |
| 분석 방법론 | 충족 | GIS suitability, Huff, Gravity, 2SFCA/E2SFCA |
| 입력 수식 | 부분 충족 | Huff, TOPSIS, AHP, WLC, 2SFCA 수식은 정리됨. 일부 원전 수식은 추가 원문 보강 가능 |
| 판단 근거 | 충족 | 국내 골목상권 매출/창폐업/폐업률/상권동향 자료 |
| 원천 생데이터 | 충족 | 서울 상권분석, 생활인구, 생활이동, 교통, 상가업소, 임대료, 실거래 |
| 전처리 기준 | 부분 충족 | 메타데이터 항목 초안은 있음. 실제 raw/standardized/scoring 구조 재설계 필요 |
| 데이터 품질 기준 | 충족 | FCSM, OECD, UNICEF, ESS, W3C, ISO, UK 품질 기준 |
| 독립 검증 | 통과 | 알고리즘 커버리지 검증 1회, 파일/카탈로그 검증 1회 완료 후 지적사항 반영 |

## 9. 한계

이번 감사의 한계:

- `pypdf`, `pdfinfo`, `pdftotext`가 없어 PDF 내부 텍스트 추출 검증은 하지 못했다.
- 일부 논문은 DOI/공식 후보로만 남고 원문을 확보하지 못했다.
- HTML 자료는 공식 페이지 중심으로 저장했지만, 추후 API 필드명/갱신일은 실제 다운로드 시 다시 검증해야 한다.
- 생데이터 자체는 아직 내려받지 않았다. 이번 단계는 자료/논문/공식 문서 수집 단계다.

## 10. 감사 결론

현재 수집 상태는 알고리즘 강화 설계 단계에 필요한 근거자료로는 통과 가능하다.

다만 실제 구현 전에는 다음 추가 작업이 필요하다.

1. 원천 생데이터 수집 스크립트 작성
2. source_metadata 테이블 설계
3. 좌표계/상권코드/업종코드 조인 기준 명세화
4. AHP/TOPSIS/Huff-lite 중 실제 1차 구현 방법 선택
5. 수식별 입력 피처와 결측 처리 규칙 문서화

## 11. 독립 검증 반영

알고리즘 강화 관점 독립 검증 결과는 다음과 같다.

| 요구항목 | 독립 검증 판정 | 반영 판단 |
|---|---|---|
| 점수화 방법론 | PASS | MCDA/WLC, AHP, TOPSIS 근거는 충분 |
| 분석 방법론 | PASS | Huff, 2SFCA/E2SFCA, GIS suitability 후보는 충분 |
| 입력 수식 | PASS | 주요 수식은 초안에 있음. 현행 백분위 점수식은 별도 공식 명세 보강 필요 |
| 판단 근거 | PASS | 국내 상권 매출/창폐업/성장·쇠퇴 자료는 충분 |
| 원천 생데이터 | 범위 밖 | 업데이트된 목표는 자료를 가져오려 시도하고 안 되면 신경쓰지 않는 것으로 변경됨. 이번 산출물은 원천 데이터 공식 문서와 수집 후보 확보까지 수행 |
| 전처리/메타데이터 | 부분 충족 | 해시/수집일/파일 크기/분류 manifest는 생성. source_id, 기준기간, 공간단위, 조인 방식, 결측률, 계보 테이블은 다음 구현 단계 과제 |
| 데이터 품질 기준 | PASS | W3C, ISO, OECD, ESS, FCSM 등 품질 기준은 충분 |

따라서 이번 산출물은 "알고리즘 강화 근거 패키지"로는 통과한다. 다만 실제 알고리즘 구현에 투입할 raw data package는 별도 단계로 수집해야 한다.

다음 단계는 논문 추가 수집보다 원천 생데이터 수집과 source metadata 설계가 우선이다.
