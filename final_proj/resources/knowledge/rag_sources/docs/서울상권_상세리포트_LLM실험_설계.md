# 서울 상권 상세리포트 — LLM 역할 비교 실험 설계

작성일: 2026-07-04
상태: 설계만 확정. 실행은 전처리 완료 → 새 알고리즘 → GT(정답 데이터) 구축 이후.

---

## 1. 실험 목적

상세리포트를 만드는 세 가지 방식 중 무엇이 나은지 데이터로 결정한다.

| 조건 | 점수를 누가 내나 | 글을 누가 쓰나 | 비고 |
|---|---|---|---|
| **A. LLM 임의** | LLM이 직접 (현행 방식) | 같은 LLM | 현재 final_proj 구조 그대로 |
| **B. 알고리즘 + 강한 LLM** | 알고리즘 | 상위급 모델 | 목표 구조 |
| **C. 알고리즘 + 약한 LLM** | 알고리즘 | 경량 모델 (예: mini급) | 비용 절감 가능성 확인 |
| **D. 알고리즘 단독** | 알고리즘 | 글 없음 (점수만) | 대조군 (ablation 기준점) |

검증하려는 주장 두 가지:

1. **"점수는 알고리즘이 내야 한다"** → A의 점수 vs D의 점수를 GT와 대조
2. **"점수가 알고리즘 것이면 글쓰기는 약한 모델로도 충분한가"** → B vs C 품질·비용 비교

---

## 2. 선행 조건 (이게 끝나야 실험 시작 가능)

- [ ] datacorpus 전처리 완료 (silver → 최종 통합표)
- [ ] 새 점수 알고리즘 확정 (컴포넌트·가중치 버전 태그 부여)
- [ ] GT 구축: A시점 데이터만으로 점수 → A+a시점(예: 8분기 후) 실측으로 라벨
  - 라벨 정의: 동업종 중앙값 대비 초과 로그성장 기준, 성공/유지/축소 3구간
  - 저기저 함정 방지: 절대 매출 하한선 병행
- [ ] 시점별 스냅샷 조회 가능한 상태 (A시점 이후 데이터가 새어 들어가면 실험 무효)

---

## 3. 평가 트랙 2개

### 트랙 1 — 점수 정확도 (A vs D)

"LLM이 매긴 점수와 알고리즘이 매긴 점수, 어느 쪽이 미래를 더 잘 맞히나"

| 지표 | 정의 |
|---|---|
| 순위 상관 (Spearman) | 점수 순위 vs GT 결과 순위 |
| 상위 10% precision | 점수 상위 10% 추천 중 실제 '성공' 비율 |
| **FP율 (핵심)** | 점수 높게 줬는데 실제 '축소'된 비율 — 추천 서비스에서 제일 비싼 오류 |
| 점수 안정성 | 같은 입력 3회 반복 시 점수 표준편차 (A는 LLM이라 흔들릴 수 있음, D는 0이어야 정상) |

- 표본: GT 전체 행 중 층화 샘플 (분기 × 업종대분류 × 점수분위). A는 LLM 호출 비용 때문에 2,000~5,000행, D는 전수 가능.
- A의 점수 출력은 D와 같은 스키마로 강제: `{score: 0~100, interval: [하한, 상한]}` — 같은 칸에서 공정 비교.

### 트랙 2 — 리포트 품질 (A vs B vs C)

"글로 쓴 리포트가 얼마나 정확하고 읽을 만한가"

| 지표 | 측정 방법 | 자동/수동 |
|---|---|---|
| 숫자 환각률 | 리포트 속 숫자 중 근거 데이터에 없는 값의 비율 | 자동 (정규식 추출 → 대조) |
| 금지 규칙 위반율 | 성공 보장 표현, 없는 월세·권리금 언급 등 | 자동 (규칙 검사) |
| 점수-서술 일관성 | 점수 40점인데 "매우 유망" 같은 모순 여부 | 자동 + 표본 수동 |
| 근거 인용 정확도 | "유동인구 상위 16%" 등 인용이 evidence와 일치하나 | 자동 |
| 서술 품질 | 블라인드 쌍대비교 (어느 리포트가 더 유용한가) — 조건 라벨 가리고 평가 | 수동 (또는 별도 LLM 심사 + 사람 표본 검증) |
| 비용·속도 | 리포트 1건당 토큰 비용, 생성 시간 | 자동 |

- 표본: 상권×업종 100~300건 (점수 분위별 층화 — 좋은 상권만 뽑으면 안 됨).
- 조건 B·C는 **같은 알고리즘 점수·같은 evidence·같은 프롬프트 틀**을 받는다. 다른 건 모델뿐.

### 부가 실험 (선택) — 재귀검증 효과

B와 C 각각을 `재귀검증 있음 / 없음` 2조건으로 나눠서 숫자 환각률·위반율이 얼마나 줄어드는지, 비용·시간이 얼마나 느는지 측정. 재귀개선 루프의 가성비를 숫자로 남긴다.

## 4. 통제 사항 (이거 안 지키면 실험 무효)

- temperature 0, structured output 강제
- 프롬프트·모델·알고리즘 가중치 전부 버전 태그 로깅 (재현 가능해야 함)
- 모든 조건에 동일한 입력 스냅샷 사용 (A시점 데이터만)
- LLM 호출 원문 요청/응답 전부 저장 (사후 분석용)
- 평가자(사람이든 LLM이든)에게 조건 라벨 비공개

## 5. 판정 기준 (실험 끝나고 뭘 결정하나)

| 결과 | 결정 |
|---|---|
| 트랙1에서 D ≥ A (예상대로) | 점수는 알고리즘 확정. A 방식 폐기 |
| 트랙1에서 A > D (예상 밖) | 알고리즘 컴포넌트 재점검 — LLM이 뭘 보고 맞혔는지 오차 분석 후 산식에 반영 |
| 트랙2에서 C가 B의 품질 90% 이상 & 환각률 동급 | 운영은 약한 모델로 (비용 절감) |
| 트랙2에서 B만 품질 기준 통과 | 강한 모델 채택, 비용은 캐싱·배치로 관리 |
| 재귀검증이 환각률을 유의미하게 낮춤 | 재귀개선 루프 정식 채택, 반복 횟수 캡 확정 |
